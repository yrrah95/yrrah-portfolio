## 這是什麼

`doubt-driven-development` 是 `addyosmani/agent-skills` 這個 repo 的 skill。
這個 repo 有 11.8 萬以上的星數，使用 MIT 授權。
這個 skill 規定 Claude 在做重要決定之前，先找一個新的審稿者來挑錯。
這一篇拆開它的 `SKILL.md`，看它怎麼對 Claude 下指令。

## 怎麼裝

1. 輸入 `/plugin marketplace add addyosmani/agent-skills`
2. 輸入 `/plugin install agent-skills@addy-agent-skills`

這個 plugin 一共有 25 個 skill。`doubt-driven-development` 是其中一個。

## 它的五個步驟

1. 寫主張：用兩三行寫下要檢查的決定，還有它為什麼重要。
2. 抽成品：只留成品和它要符合的條件，拿掉推理過程。
3. 找人挑：新的審稿者只准找問題，不准稱讚。
4. 分四類：每個問題都對回原文，再分成四類。
5. 收尾：只剩小問題，或是跑滿三輪，就停下來。

## 審稿的人拿什麼

- 給它：成品，還有成品要符合的條件。
- 不給它：你的結論，還有你怎麼想的。
- 為什麼：原文寫，給了結論，審稿者會順著說對。
- 證據要給：能推翻結論的證據，照樣要給。

## 怎麼叫它挑錯

- 先假設：寫的人太有自信。
- 不准：不准說好，不准總結。
- 要找：沒說出口的假設，還有漏掉的狀況。
- 找不到：要明講，仔細查過還是沒有。
- 別問：不能問它「這樣好嗎」，要叫它找問題。

## 什麼時候才叫它

- 要用：改判斷邏輯、跨模組、改了回不去的決定。
- 不用：改名、排版、搬檔案。
- 也不用：一行改動，一看就知道對。
- 三輪：三輪後還有大問題，交給你決定。
- 原文說：每個按鍵都懷疑，什麼都交不出去。
