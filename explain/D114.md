## 這是什麼

`ponytail` 是 GitHub 上 `DietrichGebert/ponytail` 這個 repo 的 skill。
這個 repo 有 18.7 萬以上的星數，授權是 MIT。
它叫 Claude 用最少的新程式碼解決整個問題。
這一篇不介紹成品。這一篇拆開它的 `SKILL.md`，看它怎麼對 Claude 下指令。

## 怎麼裝

1. 在 Claude Code 輸入 `/plugin marketplace add DietrichGebert/ponytail`
2. 再輸入 `/plugin install ponytail@ponytail`

README 寫明這是兩次分開的輸入。裝好之後，它在每個對話都開著。

## 規則一：動手前先看

- 先讀懂：讀懂任務，也讀這次要改的程式。
- 列範圍：列出這次改動要改到的每一個地方。
- 想後果：檢查這次改動會不會弄丟資料，或讓別處壞掉。
- 多的不算：原文寫，沒人要的功能不算在範圍裡。

## 規則二：怎麼少寫

- 做完整：原文寫，解法可以懶，改動本身不能懶。該改的地方全部改完。
- 不預留：沒人要的選項、設定、留著以後用的程式，都不加。
- 修源頭：修 bug 前，先找出哪些地方用到這段程式。然後只改共用的源頭一次。
- 留檢查：新寫的判斷邏輯要留一個小測試。很小的改動不用。
- 註明捷徑：走捷徑時，在程式碼寫一行註解。註解寫明限制，也寫明什麼時候要升級。

## 規則三：永遠不准省

- 跟安全有關的程式。
- 防止資料遺失的錯誤處理。
- 外面送進來的資料的檢查。
- 讓身障者也能用的設計。
- 你開口要的每一件事。

## 規則四：每次回完

- 回覆最後一兩行，寫它跳過什麼、沒檢查什麼。
- 你一定要知道的風險，也寫在最後。
- 整段對話都有效。說 `stop ponytail` 或 `normal mode` 就停。
